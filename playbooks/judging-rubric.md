# Judging rubric

Replace this sample with the event's published criteria and weights. Events differ: HackTX 2025 listed creativity, implementation, presentation, and learning, while TreeHacks 2025 described its grand prize in terms of innovation, functionality, creativity, complexity, impact, and execution. See [sources](../references/sources.md).

| Dimension | Judge-visible evidence | Common failure |
| --- | --- | --- |
| Problem and impact | Specific user, task, before/after, credible evidence | Broad claims without a user |
| Functionality and technical execution | Live end-to-end path, real data or labeled simulation, architecture diagram | Many unconnected screens |
| Originality | Why existing workflow fails; meaningful technical or interaction choice | Generic wrapper or cosmetic novelty |
| Usability and accessibility | Clear first action, feedback, keyboard support, readable states | Polished screenshot with dead controls |
| Sponsor fit | Required product used in the core flow, proof of API call or artifact | Logo or API name only |
| Presentation | Product demo, concise explanation, honest limitations | Slides consume the judging slot |
| Reproducibility | Run instructions, environment template, license if required | Judges cannot access it |

## Mock judge pass

Give a teammate or mentor the event's actual time limit and no prior context. Ask them to score every published criterion, name the first confusing moment, and attempt the main flow. Log the top three gaps and fix the highest-impact one. Use this loop before visual polish.

For a sponsor or theme prize, create an evidence map: requirement → code/configuration → visible demo moment → submission sentence. If a row lacks evidence, it is not ready.
