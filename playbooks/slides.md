# Slide deck for events that need one

If judging is an expo demo and slides are optional, use the product first. If a deck is required, keep it short and aligned with the event's time limit:

1. Title, user, one-line outcome.
2. Problem and evidence of the current pain.
3. Product flow: input → key moment → result (prefer screenshot or live handoff).
4. Technical architecture and why the hard part is hard.
5. Outcome: baseline vs result, test method, limitations.
6. Sponsor fit and next steps, only if relevant.

Use one idea per slide, readable type, high-contrast visuals, and source labels on external facts. Never show an unbuilt capability as current. Export a PDF backup, test the projector, and keep links to the live demo and repository accessible.
